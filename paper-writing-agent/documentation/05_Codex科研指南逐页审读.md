## 原文需说明的差异

1. 第 26 页称“以下 15 个场景”，实际第 26–31 页只编号并列出场景 1–10。按实际 10 个纳入，不补造遗漏场景。
2. 文本提取有康熙部首字形、控制字符、英文空格，以及图片表格内容缺失。逐页文本用于定位，页面渲染用于补读；不得把解析伪影变成作者错误。
3. “先让我确认”“不要立即创建文件”等出现在示例提示词内，不是当前用户对本次构建的限制。新 agent 应在用户选用这些模式或科学有效性/权限确有未决事项时停下，而不把示例变成所有任务的审批链。
4. 指南涉及宿主浏览器、桌面控制、Sites、连接器、账户、模型、定时与远程。这些属于环境能力，不能以压缩包内一个 Markdown 文件复制成离线服务。安装包内置路由、所需输入、限制、替代交付与停止点；调用时如实检查工具。
5. 原文的抽查数量、目录结构、表格数量、子任务数、轮询间隔是具体例子，保留为可选模板，不作为不可变规则。

## 六要素经验如何落实

综合 agent 先识别用户目标和交付物，定位当前事实源与风格参考，继承明确边界，选择最小充分技能组合，在需要时形成可执行计划，最后按数据、引用、文件可读性与页面实际呈现验收。图表、文献、论文、投稿信和回复信之间的同步依赖应明确；只在用户授权的范围内修正，缺失证据具体标注。
