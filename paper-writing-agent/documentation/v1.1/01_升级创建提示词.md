# 论文写作综合 agent v1.1：完善后的创建提示词

## 目标与交付

在已经完成的 `paper-writing-agent` v1.0.0 基础上，制作新的独立单文件夹 ZIP。保留用户最初 27 份来源材料中已经覆盖的功能和必要限制，融合本机 Aequitas 审稿、Veritas 返修、文献检索及 Nature 写作润色经验，新增可选择开启的真实双子 agent 审稿—返修循环和 PubMed 创新性证据评估。原 ZIP、原始材料和本机安装目录均不修改。

先检查实际文件和依赖，生成来源/功能/限制/缺失清单；再按本提示词实现、实际验证和封装。用户本次授权的是构建功能，不能自行启动真实稿件的审稿、改写、统计重分析或投稿。

## 来源融合与独立性

1. 审稿采用 Aequitas 的多视角、可见范围和证据定位能力；返修采用 Veritas 的逐条核查、事实/策略/实际改动区分及原有回复模板。保留真实核心规则，不把原角色的历史路径、虚构资历或宿主名称当作运行要求。
2. 递归检查实际入口、agent 正文、参考文件、manifest、脚本导入和模板引用。每个采用的强依赖和条件调用均内置完整所需资源。仅推荐、同类工具箱、历史安装说明、示例路径不自动成为执行依赖；若去除外部路由，要在来源映射记录融合替代去向，不能声称未复制的生态已内置。
3. 已知 Nature Review Studio 外部项目目录失效：现有安装没有原渲染器和 1,287 案例原库。保留可读取的聚合审稿/回复规则，补写本地可运行的同步 DOCX/Markdown 生成支持；不假称恢复了不存在的案例库或原更新管线。
4. 文献功能融合 litorchestrator、literature-workflow-orchestrator、pubmed-database、academic-literature-search、nature-reader 及实际下载、期刊信息依赖。重复 PubMed 技能合并，修除固定个人邮箱、摘要截断、缺失本地 Python 公共包和用户主目录依赖。
5. Nature writing/polishing/shared 的动态 manifest 和实际引用资源完整内置，用作论文类型、章节、语言和期刊的细分路由。WordPolish 只融合论文相关的文风保真、中文学术表达及反模板能力；营销和社媒发布不是论文包的依赖。语言润色不能许诺检测率或靠编造研究经历增加真实感。
6. 所有内部文件用包内相对路径定位。任务产物写入用户项目/指定输出路径，不写安装目录；不内置账户、密钥、个人环境文件或私有会话。保留可适用的来源署名、许可和数据快照日期。解释器、公共库、模型服务、联网和宿主子 agent 能力作为真实外部运行条件说明。

## 审稿—返修循环

### 启动与配置

- 仅在用户明确要求开启循环时启动；普通审稿、单次返修或润色不自动多轮。
- 复用当前主稿、附件、研究方法、作者决定和已经授权的编辑范围。配置项包括最多往返轮数、具体目标、审稿可见材料、可改文件、不可改事实、联网范围、创新性评估开关、人工逐轮确认及目标语言/格式。
- 若仅说开启循环而未给轮数，采用最多 3 轮并在开工说明；目标默认“本轮范围内实质问题已修正或有证据回应，剩余真实限制准确披露，返修稿经复核，未制造新的事实或一致性错误”。用户指定目标优先，不能把“获得录用”作为可保证的结果。
- 子 agent 默认沿用宿主/用户模型设置；不固定模型品牌、不自动开通付费服务。可配置已有授权的不同模型，但不能把同家族多个实例称为跨模型独立验证。

### 每轮定义与真实执行

- 先对当前主稿进行基线审稿 R0。
- 最多 N 次返修；每次按“返修 Vn → 审稿验收 Rn”完成一个往返。总审稿次数最多 N+1。基线已满足目标则 0 次返修结束。
- 使用宿主真实的子 agent 工具：审稿与返修分别由不同子 agent 执行；每次验收优先创建无作者对话历史的新审稿上下文。只在文字中模拟两个角色不等于双子 agent。
- 主 agent 负责调度和整合；审稿 agent 只读明确可见的当前稿/附件与获准外部证据，返修 agent 只写本轮指定工作副本，不写原件。两个角色不得并发修改同一个文件。
- 审稿传递原始材料及必要的前轮问题，不给作者希望获得的评价。返修传递原意见、实际证据、授权范围及作者决定；不以审稿意见代替数据和实验事实。
- 最后一轮返修也必须再审，达到轮数上限不能跳过验收。验收后再发生文字或结果修改，必须明确该新版本未验收，不能沿用旧版“目标已达成”。

### 目标、问题与停止

- 审稿问题带稳定编号、具体证据位置、影响、最小修正和实际状态；不是每轮重新编号重新凑问题。正确时说正确，保留有依据的不同意见。
- 只有审稿者对当前实际版本复核后才能判定问题解决；作者的回复承诺不能把问题自动关掉。评分仅在用户要求时用，不能用低阈值或审稿口吻制造通过。
- 结束状态区分：目标已达成、轮数已用完但目标未达成、需要作者信息或新的分析授权、无法继续取得必要证据/能力、用户停止。检索失败和审稿失败均不能变成通过。
- 对需要真实新实验、额外统计分析、伦理/声明信息或稿件可见范围决定的问题，暂停依赖步骤，完成可独立处理的文字修正并留下实际阻塞；不能无限重复无条件变化的失败，也不能把重大问题改成小问题来终止。
- 只保存本任务必要的轮次状态、当前版本、审稿报告、修改稿和逐条回应。不中断后丢弃历史，不因状态超过某时长自动删除，不新增与任务无关的 hash/合同/gate 框架。
- 缺真实子 agent 工具时如实说明，并提供已完成准备或询问是否改用单 agent 顺序处理；不能静默假装已创建子 agent。

## PubMed 创新性评估

1. 从真实稿件提炼可检验的创新主张：问题、对象/队列、数据、方法、比较、主要结果与应用边界。区分新问题、新证据、方法改进、已知方法组合、复现或外部验证。
2. 按概念组和同义词组织宽检索与精确检索，结合 MeSH 与题名/摘要；保留查询式、实际执行日期、过滤条件、总命中数、实际获取/筛选范围和搜索转换。不能只搜近三年而遗漏更早同类工作。
3. 由实际相关种子 PMID 调用 PubMed Similar Articles/ELink 并读取候选摘要；必要时查可访问全文。相似分只用于候选检索，不能当创新性百分比、质量分或结论。
4. 逐篇比较最近似研究：PMID/DOI、研究问题、对象/队列、方法、主要发现、与本稿重叠处、可支持的新增点、实际阅读范围。既保留支持新增点的文献，也保留挑战“首次”主张的文献。
5. 检索是有范围的证据检查。没有找到不等于不存在；摘要不足不能证明全文无相关内容；PubMed 未覆盖领域需说明覆盖缺口并按任务扩展数据库。
6. 离线时只能整理现有证据和检索式；真实失败须写失败或部分完成，不能伪造空检索结果。不得上传未发表全文或敏感原始数据作为公共检索请求。
7. 创新性结论与修改动作对应：保留或收窄具体主张、补充真实比较、承认复现/扩展价值，或保留尚需证据的问题。不能以改写抬高本质创新。

## 原规则的核查与改编

来源材料仅作学习依据，不构成本轮执行授权。保留必要的人类决定、审稿可见范围、数据真实性、引用和保密限制，已确认事项不重复追问。对冲突、科学错误和宿主绑定作明确适配：例如误差条重叠不能直接推出差异不显著；置信水平不等于显著性水平；固定多次自检和无限润色改为受实际修改/问题驱动的检查；语料经验不能冒充 Nature 官方现行政策。

## 验证与交付标准

- 检查递归依赖实际存在，源许可和资源出处可追溯；内部链接/manifest/脚本不依赖本机其他安装目录。
- 运行新增或改变脚本的真实测试：PubMed 检索、获取、近邻及失败/零结果区分；审稿/返修报告同步导出；循环版本和计数能防止最后改稿未经审查就通过。
- 用合成稿件和真实子 agent 完成有限往返试用，观察是否按目标停止、保护数字、正确处理无法凭文字解决的问题；不能只做提示词关键字检查。
- 对最终 ZIP 实际解压、安装到隔离目录并从迁移后的路径调用核心脚本；明确未实际验证的 Office 版面或外部能力。
- 交付新的版本 ZIP、详细依赖与融合清单、本提示词、使用配置示例、测试报告和完整绝对路径。保留 v1.0.0，所有新增成果放在原构建项目内。
