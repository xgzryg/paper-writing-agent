## 3. 实際发现的流程问题

1. **轮数歧义与最后稿未审**：原文每轮“先审后改”，MAX_ROUNDS 轮完成修改后即可退出；最后交付稿可能没有任何针对该版的验收。改为基线审稿 R0，最多 N 次返修，每次后必须审稿 R1…RN。
2. **过期即删除**：部分入口把超过 24 小时的状态文件直接删除；另一个共享文件又要求询问，来源自相冲突。恢复应依据当前文件、阶段、子agent 和待完成工作实际状态；不按时间判废，不删除用户旧记录。
3. **评分不等于目标完成**：6 分且 almost 会停，但“almost”可能仍含关键阻断。本包按约定目标和逐条证据判定，评分只在用户需要时作辅助；不承诺期刊接收。
4. **预设有错、强对抗与研究范围**：来源提示 reviewer 假定工作坏了；会鼓励制造问题。论文审稿应主动检查真实风险，明确正确项，并区分重大问题、建议、不可通过改写补足的证据缺口。
5. **跨模型包装**：来源同族 reviewer 仅为 provisional，却有共享资源强制跨族的复杂验收体系。本包如实记“独立子agent/实际模型族已知或未知”，不把同族两角色宣称为跨族独立或外部期刊认可，也不为这一任务加外部模型门槛。
6. **授权越界**：读取配置后自动飞书通知、调用外部模型、部署实验与无限监控均不是建包或普通论文返修的自动授权。创建功能不启动真实稿件循环；使用循环仅执行已授权文字、核查和分析范围。
7. **恢复粒度错误**：原状态只存 round，恢复直接 round+1，若上一轮仅完成返修或审稿请求失败，会跳过尚未完成的验收。本包应保存具体阶段与稿件版本，先完成当前必要阶段。
8. **内容输入冲突**：独立性协议禁传前轮反馈，循环又要求传；协议末尾允许同审稿人引用自己的反馈。可用当前稿和原证据独立初判，再回看原始前轮问题核销；禁止作者/返修者摘要取代读稿。
9. **无关输出泛滥**：全量时间戳副本、claims、方法图、HTML、MANIFEST、事件流并非每稿必需。使用每轮目录和一个状态/汇总足够，保留原始意见和可追溯稿件，不复制整个流水线。
10. **特定宿主脆弱绑定**：`spawn_agent`/`send_input`/MCP 名称、模型/推理档位、Unix shell 均随宿主变化。先探查可用工具并按实际 schema 调用；不编造后台执行或成功。

## 4. 可执行的最小循环

### 配置与轮数

循环是显式开启的可选分支。接入用户当前指定稿、必要表图/补充材料和约束；以用户给出的最大往返次数 N 和目标为准。单纯“审稿”不自动循环，创建本功能不等于开始审稿。需要用户决定的关键缺失仅在真正启动稿件循环时询问。

`R0` 是基线审稿，不消耗返修轮次。第 i 轮 = 返修者依据最近一次审稿对 Vi-1 生成 Vi + 审稿者针对 Vi 完成 Ri。最多 N 次返修和 N+1 次审稿；最后一次审稿不再次触发第 N+1 次返修。

例：N=1，V0 → R0 → V1 → R1 → 停止。R0 已达目标时，0 次返修即可结束。R1 未达目标且 N=1 时，仍交付 V1、R1 和剩余问题，明确“达到轮次上限，目标未达成”。Ri 工具失败不计“已完成往返”，且 Vi 标记“待审/审稿失败”，不可借 Vi-1 的判定宣布 Vi 达标。

### 两个真实执行角色

主 agent 负责调度、状态和交付；审稿子agent 与返修子agent 必须是两个真实独立工具实例。优先不继承完整作者对话，仅收到角色说明、目标、当前稿/原始材料路径及允许的任务范围。审稿者只读稿件及证据，写自己的评语；返修者只写本轮新稿、逐条处理表和需要的回复信，不改原评语或声称自己已通过审稿。文件写入区域分开，返修与审稿按依赖顺序执行。

可维持同一审稿子agent 连续追踪自己的意见。若宿主上下文不可靠，新开 reviewer 时传原始意见及当前稿路径，并要求先读当前稿独立判断、后核销旧意见。记录实际 agent id 和可得的模型信息。宿主没有真实子agent 功能时说明能力缺口，可交付两份任务简报供人工分开执行；除非用户改变要求，不能在单会话扮两角色后宣称完成真实双agent循环。

### 基线审稿 R0

1. 读当前稿与授权材料，识别文章类型、目标期刊/用途、证据和缺失范围。
2. 选择已内置审稿、方法核查、图表/数值/引用等必要分支；不固定启用所有维度或强凑问题数。
3. 创新性开启时先形成可核查的主张拆分及 PubMed 检索，再完成与最近相似研究的比较。
4. 输出原始评语和问题记录：问题 ID、原文位置、问题及其证据、严重性、最小合理处理、是否需要新增数据/分析/作者决定。
5. 主 agent 检查针对当前版本的目标是否已满足；若满足可结束。

### 返修 Vi

每条问题可为接受、部分接受或有证据不接受。只对用户授权范围实施已接受修订，保留数值、方向、样本量、定义和研究限制；需要重新分析时复用真实数据/现有代码，并在已授权范围内完成后再写入论文；未做或无法做的分析只能明确列为待办/局限，不能编造完成结果。

若审稿者要求不合研究设计、P 值导向、改变终点或假设、抹去负结果、过度自我防御，返修者应说明理由并提交证据供审稿者裁定。单纯语言审稿不得触发数据模型重拟合。产物须含实际稿件变更及定位，回复信区分“已完成”“拟开展”“无法完成”。

### 复审 Ri 与停止

审稿者读 Vi 和真实证据/差异，对上轮每个问题核销为已解决、部分解决、仍待证据、基于证据撤回、不适用于目标；同时检查本轮变更是否引入科学错误。作者回复只是待核查的陈述，不能自行作为问题关闭的证据。

目标满足以用户约定及当前稿证据为准：应处理的目标相关阻断已解决、关键陈述有来源、稿表图一致、授权约束满足。明确作为局限接受的研究边界不必凭空变成新的实验义务。存在关键未知时写“无法判定”，不能当通过。创新性不足也不能靠换措辞自动通过。

停止原因分开记：目标达成、轮次上限、用户停止、需要关键输入/权限、工具失败、无可执行改进。连续出现同一缺失或纯措辞往复时先核实原因，不通过无依据加分、换审稿人碰运气或重复检查来消耗剩余轮次。

## 5. 创新性：PubMed 的证据规则

本报告只设计流程，没有为某篇真实稿件联网检索，也不声称创新性已经核查。

从问题、人群/模型、暴露/干预、比较、结局、数据、方法、机制和贡献逐项拆解 novelty claim；拟定核心同义词与组合检索，既查近期最相似研究，也查可能更早的直接先例。时间窗口是筛选条件，不能把近三/五年检索替代全部先例核查。

保存数据库、实际检索日期、检索式、筛选范围、命中/筛选情况、PMID/DOI、题名/年份、可得摘要或原文定位。用 PubMed 主记录识别文献；需要方法/机制细节时读全文，只有摘要的项目明确标记。可以用 PubMed Similar Articles 拓展候选，但“相似”排序不等于证明贡献重合。核实结果内容后建立“本稿主张—最近先例—相同点—增量—仍未验证部分”表。

结论应区分：已有直接先例、主要为增量扩展、在本次检索范围内有可支持差异、信息不足。检索无结果只说明本次策略未找到，不能推出世界首创；PubMed 覆盖不到的工程/算法部分可建议并在获准联网范围内补充相应数据库，不以 PubMed 一库判断所有学科。引用存在不等于支持具体主张，当前元数据查询成功也不等于读过全文。

无网/用户禁网：只用用户提供或本地可读的文献形成“基于现有材料的暂定比较”，同时交付待执行检索式；不得伪造 PMID/DOI、访问日期、检索命中或“没有近似文献”。如果“完成实时 PubMed 创新性核查”属于停止目标，则此项不能标记完成，其他不依赖网络的返修仍可执行。

## 6. 状态与恢复的最小记录

建议一个运行目录，内含 `state.json`、简明汇总、各轮审稿原文、各轮稿件和处理表。无需新增 hash、复杂 gate、冻结 contract、事件总线或外部数据库。

状态至少含：当前输入稿路径/用户版本标识、目标、N、已完成返修轮数、当前阶段、当前稿路径、最近已审稿路径、审稿/返修 agent id、最近评语路径、未解决问题及依赖、停止原因。仅主调度者改状态。阶段在启动子任务和确认其产物后更新，避免崩溃后不知道请求是否已发出。

恢复时先查对应子agent 是否仍在运行、已写出结果是否可用、输入有没有用户修改；已完成阶段复用，从真正未完成的阶段继续。不得因为状态已过 24 小时就删除；也不得在恢复时无条件 round+1。失败先读错误及已有输出，避免重复启动、覆盖已有改稿或将未完成稿标记为已审稿。用户人工更新当前稿后，重新绑定本稿并核查受影响结论，旧审稿结论不能自动继承。

## 7. 建议验收情境

- 基线直接达标：1 次审稿、0 次返修，正确停止。
- N=1 未达标：V1 必须有 R1，停止为轮数到达而不是达标。
- 审稿失败：不伪造通过，不算完成往返，保留最后已审版本。
- 返修提出不存在的新增分析：审稿者应拒绝这段陈述；已完成/拟开展区分正确。
- 用户禁网但开启创新性：不给实时已核查结论，能继续文字/一致性修订。
- 新证据反驳旧审稿意见：可撤回旧问题，不为坚持角色而制造问题。
- 同族两个真实agent：真实隔离可报告，不宣称跨族或期刊接收。
- 中断发生在 Vi 完成后 Ri 开始前：恢复执行 Ri，而非跳到下一轮。

这些情境应通过真实小型虚构稿件或模拟工具状态验证流程，不得把虚构测试内容当科研结果。
