# v1.1 使用说明

调用名仍是 `$paper-writing-agent`。只安装一个 `paper-writing-agent` 文件夹，内部技能按路径调用，不要求把几十个子技能散装到全局目录。安装包保留v1.0的写作功能，并融合本机审稿、返修、文献和Nature写作润色。

## 常用请求

### 多视角审稿

```text
请使用 $paper-writing-agent，以Aequitas审稿。
正文和补充材料可以读取，代码和作者内部笔记不在审稿范围。
指出真实的实质问题、证据位置和最小修正；没有问题的部分明确说明。
```

### 单次返修

```text
请使用 $paper-writing-agent，用Veritas按这份审稿意见修订当前工作稿，
同时准备逐条回复。沿用我已确认的方法和统计结果。
未做的新实验或分析列为待办，不写成已经完成。
```

### 开启连续循环

```text
请使用 $paper-writing-agent，开启审稿—返修循环，最多3轮。
审稿和返修使用不同的真实子agent；正文和补充材料可见。
目标：本次范围内重大问题已解决或有证据回应，正文、图表和回复一致，最终稿经再审。
只允许修改工作副本文字；需要新分析时先列出。
不必逐轮等我批准，但遇到研究方案或作者事实缺项时明确说明。
```

### 同时评估创新性

```text
请使用 $paper-writing-agent，开启最多2轮审稿—返修循环，并加入PubMed创新性评估。
查找与核心问题、队列和方法最接近的研究，保留检索式、PMID/DOI、实际阅读范围和逐篇比较。
目标是使创新主张准确且有证据支持；不要为了通过而夸大贡献。
```

### Nature写作与润色

```text
请使用 $paper-writing-agent，按Nature Communications的论证风格润色Discussion。
保留现有数据、引用、结论边界与作者声音；避免返修后重复堆叠解释。
```

输入中文不会自动翻译为英文；目标语言按请求确定。精确字数、格式、数据披露与期刊政策在实际投稿任务中按当前官方来源核对，语料经验不冒充官方规定。

## 循环如何计数

先进行基线审稿 R0，再进行最多N次返修及验收：

```text
当前稿 → R0审稿
          ├─ 目标已达成：停止，0次返修
          └─ 返修V1 → R1再审
                        ├─ 目标已达成：停止，完成1轮
                        └─ 返修V2 → R2再审 → …… → VN → RN再审
```

最多3轮意味着最多3次返修、最多4次审稿。轮数用完仍必须审查最后改稿；如问题未解决，状态是“达到上限，目标未达成”，不会变成“通过”。用户可以指定目标和轮数；未给轮数时默认3轮。普通审稿不会自动进入循环。

可选开启每轮人工确认；已经给出的确认、范围和作者事实会复用。缺真实子agent工具时明确报告，不用两个角色口吻冒充两次真实委派。宿主槽位暂满时等待已有任务完成后再继续；等待或发起成功不等于审稿完成。

## 资料与原件

真实工作稿、审稿意见、回应和必要状态保存在任务项目内。原稿和已受审版本保留，每次新改动对应明确版本，避免旧审稿结论套到新稿。复用恢复状态时先检查实际文件和已完成阶段，不从零重做。

安装包 `sources/` 中是原貌追溯资料，部分收在内部ZIP中，里面的历史路径、旧角色规则和示例不执行。本机已安装agent与旧v1.0压缩包不受此次升级影响。

## 已知运行条件

文本工作需要模型宿主读取包内文件；双子agent循环需要真实委派工具。PubMed新执行器只用Python标准库且无API key可低速使用；实时文献仍需联网。Word生成、浏览器全文下载、Office/TeX渲染分别按实际任务使用现有环境，本包不自动安装库或账户服务。

本机NRS没有原1287案例库，包内提供的是实际取得的聚合规则与新实现的报告工具。PubMed近邻分值只用于找候选文章，创新性结论来自对具体文献与本稿的证据比较；有限检索不证明全球首次。
